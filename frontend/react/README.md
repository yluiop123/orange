# ORANGE React frontend

React 19 + Vite implementation, and the reference frontend for Orange; this page covers installation, commands, layout, dependencies and deviations only, and does not repeat the architecture.

## Environment and installation

- Node.js (version pinned by Vite 8) and pnpm; `package.json` sets `packageManager` to `pnpm@12.15.0`.
- This directory ships its own `pnpm-lock.yaml`; install with pnpm.

```bash
cd frontend/react
pnpm install
```

Local development enables mock by default: `.env.development` sets `VITE_MOCK_ENABLE=true`, demo account `super / super`. `.env.local` is ignored by the `*.local` rule and only affects your machine; note that Vite's precedence is `.env` < `.env.local` < `.env.[mode]`, so turning the dev mock off requires `.env.development.local` or a process environment variable — writing `.env.local` gets overridden by `.env.development`.

## Commands

| Command | Actually runs | Purpose |
| --- | --- | --- |
| `pnpm dev` | `vite` | Dev server, port from `VITE_PORT`, default 5173 |
| `pnpm build` | `tsc -b && vite build` | Production build after type checking |
| `pnpm build:github` | `tsc -b && vite build --mode github` | GitHub Pages build, base `/orange/` |
| `pnpm preview` | `vite preview` | Preview the production build |
| `pnpm preview:github` | `vite preview --mode github` | Preview the Pages build |
| `pnpm lint` | `eslint .` | ESLint |
| `pnpm typecheck` | `tsc -b` | Type checking only |
| `pnpm test` | `vitest run` | Unit tests (`src/**/*.test.ts`, node environment) |
| `pnpm test:watch` | `vitest` | Watch mode |
| `pnpm gen:api` | `openapi-typescript ../../contracts/openapi.json -o src/api/schema.d.ts` | Regenerate types from the contract |
| `pnpm analyze` | `cross-env ANALYZE=true vite build` | Emit the `dist/stats.html` bundle report |

## Directory structure

```text
frontend/react/
  public/mockServiceWorker.js   MSW worker
  src/
    api/            axios request wrapper; schema.d.ts is generated
    auth/           access token, refresh, session hint
    components/     ui/ (generated by shadcn), ext/, system/, shell components
    config/         permissions.json (synced copy), menu-icons.ts
    hooks/          use-mobile
    lib/            axios, access, path, menu, page-routes, tree-code
    locale/         zh-CN.ts, en-US.ts
    mock/           MSW handlers and in-memory data
    pages/          one directory per Page Path, pages must be index.tsx
    store/          zustand: user, menu, permission, theme, locale
    themes/         seven colour-scheme CSS files
    App.tsx / layout.tsx / main.tsx / index.css
  .env / .env.development / .env.github
  vite.config.ts / vitest.config.ts / components.json
```

## Relationship to the contract

- The contract is `contracts/openapi.json`. `pnpm gen:api` generates `src/api/schema.d.ts`; the file header states it is generated by openapi-typescript and is not edited by hand.
- `src/api/system/*.ts` compose the `User`, `Role`, `Group` and `Permission` types used by pages from `components["schemas"][...]`, then send requests and return `data`.
- The Axios base URL is `VITE_BASE_API`, default `/api/v1/`; the instance always sends `Authorization` and `Locale`, and handles single-flight refresh on 401, plus 403 and 40302.
- The contract change flow is generate first, then update call sites; endpoints and error codes are not repeated on this page — see the [HTTP contract](../../contracts/openapi.json).

## Conventions and deviations of this stack

- Routing is fixed on `HashRouter`, with no routing-mode switch; page paths are collected automatically from `pages/**/index.tsx` by `src/lib/page-routes.ts`, so new pages do not touch the route table.
- Mocking uses MSW; `src/main.tsx` dynamically imports `src/mock` only when `VITE_MOCK_ENABLE=true`.
- Menu titles come from `GET /api/v1/auth/menus`, like the other two stacks; no `menu.<path>` translation keys are shipped.
- The theme is CSS variables: `<html class="dark">` plus `theme-<color>`, with state stored under `theme-mode` / `theme-color`.
- `build:github` produces a build deployed at `/orange/`; CI publishes React to GitHub Pages on push only.
- Unit tests run in the node environment and cover access, path, the permission catalog, tree-code, page-clamp and permission merging; there are no DOM component tests.
